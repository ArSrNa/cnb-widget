# 产品意图

## 定位

macOS、Windows、Linux 常驻 widget，参考 CodexIsland 展示 Codex 用量的形态，聚合展示 **CNB 平台**的工作状态与资源用量。

## 应用分区（2026-10-13 需求）

应用分为两部分，职责分离：

| 分区 | 表面 | 职责 |
|---|---|---|
| **展示层** | 灵动刘海（Notch）+ 悬浮球（Float） | 展示基础用量（进度环/百分比）、展开后看详细用量与 issue NPC 对话情况 |
| **控制层** | 主面板（Panel） | 工作台：数据细看（用量详情 / NPC 动态）+ 设置、连接（cnb-cli 安装/登录），并**控制展示层的显隐与内容口径**（左右布局见 [panel.md](./panel.md)） |

- 主面板与气泡面板分工：气泡 = 瞥一眼（随用随收），主面板 = 坐下来看（完整明细 + 设置，布局见 [panel.md](./panel.md)）；
- 主面板控制项：是否展示悬浮球 / 灵动刘海、悬浮球用量展示的**组织与维度**（credit / 云原生开发核时 / 云原生构建核时）；
- 灵动刘海**仅 MacBook 刘海屏可用**（能力探测，见 [display.md](./display.md) §5），不满足时主面板开关禁用。

## 核心用户场景

开发者在 CNB 上同时维护多个组织、跑多个 NPC 任务：

1. **资源感知** — 不切换窗口，瞥一眼悬浮球/刘海就知道各组织 credit、核时还剩多少；
2. **工作感知** — 一眼掌握当前 CNB 上 NPC 的状态：哪些在跑、哪些在等我回复、哪些失败了。

## 展示形态（按屏幕能力与用户配置）

| 屏幕 | 形态 |
|---|---|
| 有刘海的内建屏 | 灵动刘海（可开关）+ 悬浮球（可开关），各自独立 |
| 无刘海屏 / 外接屏 | 仅悬浮球 |

## 设计原则

- **瞥一眼**：idle 态信息密度极低，展开后逐级呈现（球/胶囊 → 详细面板）；
- **不抢焦点**：全程不激活自身，不干扰当前工作；
- **可配置**：展示什么、按什么口径统计，由主面板设置决定（见 [data.md](./data.md)）。
