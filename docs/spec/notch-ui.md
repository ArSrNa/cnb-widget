# 刘海 / 悬浮球 UI Spec

> 2026-10-13 需求评估定稿：展开形态 = 悬浮球旁气泡面板（NSPanel）；口径 = 单选组织 × 维度；刘海点击与悬浮球一致。

> 2026-10-13 展示调整已实现：刘海直接位于菜单栏，左侧仅展示百分比圆环，右侧上下两行展示数量与状态，数量为较大白字，状态为灰色小字，两行水平居中、整体垂直居中；左右两侧等宽，内容均为 28×28；主面板「设置 → 刘海展示」配置组织、用量类型和状态，持久化并即时广播。当前数据已接入真实 CNB 组织用量与 NPC 状态；hover 时刘海自身展开为一个连续的黑色组件，点击刘海仅展开详情，只有点击展开区域中的「打开工作台」按钮才打开主面板。

## 1. 双表面（Surface）模型

| 表面 | 触发条件 | 形态 |
|---|---|---|
| 刘海胶囊 | 内建刘海屏（见 §4 探测）+ 用户开关开启 | 贴合刘海两侧的胶囊，与刘海视觉融合 |
| 悬浮球 | 用户开关开启（任意屏幕可用） | 360 加速球形：外圈进度环 + 内圈百分比，可拖动 |

- 两表面显隐由主面板设置独立控制（settings `notchEnabled` / `floatEnabled`，已实现）；
- 灵动刘海在探测到无刘海屏时强制隐藏，主面板开关禁用并附提示；
- **当前点击行为**：刘海仅展开自身，展开组件内的「打开工作台」按钮唤起主面板；悬浮球仍直接唤起主面板。独立气泡详细面板（§3.2）为后续规划。

## 2. 形态状态机（NotchSurface）

```
idle ──hover / click──▶ peek ──点击「打开工作台」──▶ main
  ▲              │
  └────── mouse leave ◀┘

idle/peek 之上可叠加 event 横幅（6s 自动收回）
```

| 形态 | 内容 | 尺寸（逻辑像素） |
|---|---|---|
| **idle** | 左侧：所选组织与类型的用量环 + 百分比；右侧：上方数量、下方灰色状态小字，居中排列 | 原生刘海宽度 + 128 × 菜单栏高度 |
| **peek** | 刘海整体展开放大，同一组件内展示当前用量类型的全部可读组织用量条、各状态计数及「打开工作台」按钮；组织列表内部滚动 | 宽度至少 520，高度为菜单栏高度 + 200 |
| **event** | 「NPC ✅ 完成 xxx」「NPC ❌ 失败 xxx」横幅 | peek 尺寸，叠加于当前形态之上 |

- **展开 / 收起动画**：尺寸、圆角、头部大小、数字和详情统一使用 400ms、`cubic-bezier(0.4, 0, 0.2, 1)`；移出后等待 200ms 再收起。展开前原生窗口预留透明空间，收起动画完成后再缩小窗口，避免裁切。详情收起后设为 inert，不接收点击与键盘焦点；尊重系统减少动态效果设置。
- **未聚焦悬停**：macOS 通过不拦截点击的原生 NSView 和 `NSTrackingArea.ActiveAlways` 向刘海窗口发送进入 / 离开事件；其他应用或窗口处于前台时仍可 hover 展开，无需点击或抢焦点。焦点离开但鼠标仍在刘海内时保持展开。

- 原「panel 完整面板」形态从刘海状态机移除，由气泡面板承载（§3.2）；
- 无刘海屏 hover 语义不变：idle → peek。

## 3. 悬浮球（Float，已实现拖动/显隐，进度环与气泡面板待实现）

### 3.1 idle 球体

- 窗口 64×64 逻辑像素，透明背景（现状）；
- **外圈进度环**：CSS `conic-gradient` 或 SVG 弧线（自绘，组件库不覆盖，符合「仅表面自绘」约定）：
  - 弧度 = 口径百分比 × 360°；用量 > 80% 环色变红（`#f87171`），否则主色（`#818cf8`）；
- **内圈百分比**：整数数字，同口径；
- **口径（定稿）**：单选组织 × 单选维度 —— settings `usageMetric`（credit / git-storage / object-storage / ci-corehour / dev-corehour / dev-gpu-corehour）× `usageOrg`（主面板指定单个组织）；
  - 所选组织 charge 403 或数据缺失 → 显示 `--`（气泡面板内提示无权限）；
  - 刘海 idle 左胶囊与悬浮球**共用同一口径配置**，行为一致；
- 拖动交互使用 `float_nudge` / `float_settle`；超过位移阈值后移动窗口，低于阈值仍视为点击，位移请求按帧合并。

### 3.2 气泡详细面板（Bubble，定稿）

- **承载**：独立窗口，NSPanel（`tauri-nspanel`）+ nonactivating，不抢焦点（提前引入，原 M4 项）；
- **触发**：悬浮球 / 刘海胶囊点击（位移 < 阈值）；
- **定位**：悬浮球触发时贴球弹出（默认球体下方，靠近屏幕边缘自动翻转）；刘海触发时从刘海下方弹出；
- **尺寸**：约 480×360 逻辑像素，内部滚动；
- **收回**：点击面板外部 / Esc / 再次点击表面；
- **内容（全部监控组织）**：
  1. 用量余额区：逐组织 × 六维度（AI Credits / 代码仓库存储 / 对象存储 / 构建 CPU / 开发 CPU / 开发 GPU）已用与剩余进度条；只列出已成功读取额度与用量的组织，过滤 403 或请求失败的组织；全部列出，不设置数量上限，超出详情高度时滚动；
  2. NPC 对话区：状态计数（工作中 / 已回复 / 失败）+ 活跃 issue 列表（状态徽标 / 仓库 / 标题 / 最后动作时间，点击浏览器打开 issue）。

## 4. 刘海屏能力探测（新增，替代原 CGDisplayStream 全量方案）

「灵动刘海仅 MacBook 刘海屏可用」的探测，按优先级：

1. **`NSScreen.safeAreaInsets`**（macOS 12+）：主屏 `safeAreaInsets.top > 0` 即有刘海 —— 无需屏幕录制权限，走 objc2 调用（Tauri 主进程）；
2. 硬件型号兜底：`sysctl hw.model` 对照已知刘海机型清单（MacBook Pro 14″/16″ 2021+、MacBook Air M2+）；
3. 探测结果通过 command 暴露给前端（`notch_available`），主面板据此禁用开关；运行期显示器热插拔重探（外接屏不影响内建屏判定）。

> 原 notch_probe（CGDisplayStream 探测刘海 frame 精确贴合）保留为 M4 增强项；本节探测只回答「可用/不可用」，无权限要求，提前至 M2 实施。

## 5. 窗口实现

- 刘海：单一透明窗口（`transparent + decorations:false + alwaysOnTop + skipTaskbar + shadow:false`）承载 idle/peek。macOS 使用 AppKit 主线程设置 `NSStatusWindowLevel + 1` 与原生完整屏幕 frame，避免落在菜单栏下；通过 `safeAreaInsets.top` 和 `auxiliaryTopLeftArea` / `auxiliaryTopRightArea` 获取刘海高度、宽度和中心，优先选择有刘海的屏幕（含非主屏），中央预留摄像头区域。左右两侧均宽 64，内容水平与垂直居中；切换形态时保持中央空白与物理刘海对齐。idle 态窗口仅占刘海与两侧组件范围；
- 悬浮球：独立透明窗口 64×64，可拖动、位置持久化（已实现）；
- 气泡面板：独立 NSPanel 窗口（§3.2），默认隐藏，按需弹出。

## 6. 主面板（Panel，工作台）

主面板为工作台（左右布局、一级导航、用量详情下组织二级菜单），布局与密度规范见 [panel-ui.md](./panel-ui.md)；本节仅汇总由主面板承载的设置项：

- **显示**：灵动刘海开关（无刘海屏时禁用 + 提示）、悬浮球开关；
- **用量口径**：维度单选（AI Credits / 代码仓库存储 / 对象存储 / 云原生构建-CPU / 云原生开发-CPU / 云原生开发-GPU）× 组织单选（选项 = 组织白名单 ∩ owner 组织；白名单机制见 intent/data.md §3）；
- **右侧状态**：单选工作中 / 待回复 / 失败，分别对应 `NPC_WORKING` / `NPC_REPLIED` / `NPC_FAILED`，统计全部监控组织的对应状态数量；
- **连接**：cnb-cli 状态 / 安装 / 登录引导（SetupView，已实现）。

## 7. 设置项汇总（主面板承载）

| 设置项 | 存储 | 默认 | 状态 |
|---|---|---|---|
| 灵动刘海显隐 | `notchEnabled` | 开 | ✅ 已实现（无刘海屏禁用并隐藏） |
| 悬浮球显隐 | `floatEnabled` | 开 | ✅ 已实现 |
| 悬浮球位置 | `floatPos` | 主屏右侧 1/3 处 | ✅ 已实现 |
| 用量维度 | `usageMetric`：credit / git-storage / object-storage / ci-corehour / dev-corehour / dev-gpu-corehour | credit | ✅ 已实现 |
| 用量组织 | `usageOrg`：单选 | 首个可读取组织 | ✅ 已实现（真实所属组织，权限不足的组织不可选） |
| 右侧状态 | `notchStatus`：NPC_WORKING / NPC_REPLIED / NPC_FAILED | NPC_WORKING | ✅ 已实现 |
| 面板字段显隐、组织白名单 | — | — | M3（见 intent/data.md §3） |

- 设置变更经 `settings-changed` 事件广播，刘海/悬浮球/气泡即时生效（现状已有）。

## 8. 完整可读组织列表

刘海展开区与悬浮球详情窗共用 SurfaceUsageList：逐组织排除 chargeForbidden 或请求失败，保留所有可读组织，不再截取前 4 个。所选维度缺失或零总额度显示 --，其他有权限组织仍完整列出。组织列表使用固定高度内的 ScrollArea，并在溢出时显示滚动条。

悬浮球点击打开独立 Tauri 详情窗，定位于球旁并限制在当前屏幕工作区域；失焦、Esc、关闭按钮隐藏窗口，工作台入口放在详情页。关闭悬浮球同时隐藏详情窗。当前普通详情窗点击后获得焦点；nonactivating NSPanel 属于后续增强。
